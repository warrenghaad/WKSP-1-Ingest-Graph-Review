## Control plane definition

The control plane is the room/prism shell and orchestration surface.

It owns:

- room and prism behavior
- node registry and graph surface
- stage boards and assembly surfaces
- session state
- queue and review surfaces
- provenance-visible review
- handoff and dispatch
- package prep before downstream delivery

It does not own semantic interpretation, annotation generation, research understanding, or image sourcing logic.

## Functional buckets that belong in the control plane

### Room / prism shell

- room canvas
- prism rotation
- dock
- drawers
- inspector
- window manager
- graph surface
- node registry

### Session / review

- local session state
- queue state
- candidate review surface
- DAM lane visibility
- provenance display
- six-decision review UI

### Assembly / stage management

- section stage board
- lesson assembly surface
- drag-drop composition
- evidence visibility before commit
- package prep

### Routing / dispatch

- send selected node
- send active lesson
- queue distilled output
- publish to Engine 4
- handoff tray

## What the control plane should not own

- ingest understanding
- annotation generation
- summarization
- concept extraction logic
- image search logic
- image curation logic
- research-query generation
- writing and distillation semantics
- fidelity-analysis logic itself

## Bottom line

The control plane is the place where the work is staged, reviewed, assembled, and dispatched.

It is the NASH room shell, not the semantic brain.
