# Replit's Job Right Now

Date: 2026-03-23

## One-Sentence Job

Replit's job right now is to be the first-run textreader and image-prep worker for the main app.

It should take text or uploaded files, ingest them into the real backend immediately, source and evaluate images, display them in a lightweight DAM view, and hand reviewed packets back to the canonical app.

## What Replit Is

Replit is:

- a first-pass reader
- a file and text intake worker
- a concept extractor
- a search query generator
- an AI prompt generator
- an image candidate curator
- a vision-fidelity checker
- a temporary lightweight DAM surface
- a handoff worker back into the main backend

## What Replit Is Not

Replit is not:

- the CMS
- the NASH room
- the RWI system
- the canonical DAM
- the lesson editor
- the graph authority
- the approval source of truth
- the final storage layer

The main app and backend remain canonical for runtime records.

Notion serves as the CMS, workflow, validation, and checking layer.

## The Required Order Of Operations

Replit must do the work in this order:

1. Accept pasted text or uploaded files.
2. Create a local draft session.
3. Ingest the material into the real backend immediately.
4. Extract atomic visual concepts from the ingested material.
5. Call the vision spec layer so overlays, patterns, hover cards, and graph-ready packets are created at the same time.
6. Generate search queries and AI image prompts for each concept.
7. Source image candidates.
8. Display the candidates immediately in a lightweight DAM view.
9. Run vision fidelity checks on the candidates.
10. Let the user mark each candidate with an explicit review decision.
11. Send reviewed runtime packets back to the canonical backend.
12. Update the Notion workflow and validation layer with status, review state, and ready-next signals.

## The Review Decisions Replit Must Support

Every candidate image must support these decisions:

- `approve_reference`
- `reject`
- `needs_ai_generation`
- `needs_overlay`
- `needs_crop_or_resize`
- `needs_better_source`

Replit is not allowed to collapse this into only approve and reject.

## The UI Replit Must Provide

Replit must provide:

- a left intake pane for text and files
- a center concept board
- a right candidate and metadata drawer
- an immediate lightweight DAM area for ingested items and image candidates
- visible provenance badges
- visible fidelity badges
- hover-ready text and image metadata

Image cards must use bounded containers with `object-contain`, not default crop behavior.

## The Backend And Notion Relationship

Replit must treat the external app backend as canonical for runtime data, and treat Notion as the CMS and workflow control plane.

Replit should call:

- `POST /api/research/ingest`
- `POST /api/vision/spec-and-graph`
- `POST /api/images/search/multi` or `POST /api/rwi/images/auto-search-needs`
- `POST /api/images/validate`
- `POST /api/images/analyze`
- the existing handoff and approval routes in the main app backend

If the backend is offline, Replit may export JSON as a fallback, but that is only a temporary fallback.

Replit should also write workflow-facing status to Notion, but Notion should not replace the runtime image tables as the canonical data store for candidate blobs or final media metadata.

## The Standard Replit Rule

Replit should never become a second system.

Its job is:

- ingest early
- source fast
- validate fidelity
- show candidates clearly
- collect explicit review decisions
- hand everything back to the real app

## The Simplest Way To Remember It

Replit is the intake, sourcing, and first-pass curation worker.

It is not the place where the project becomes final.
